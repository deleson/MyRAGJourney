# 新人入门指南（MyRAGJourney）

## 1. 项目定位
- 这是一个学习导向的 RAG + Agent 实践项目，技术栈是 Django + LangChain/LangGraph + Streamlit。
- 目标是打通“文档上传 -> 向量化 -> 检索增强问答”以及“可调用工具的智能体”两条主链路。

## 2. 顶层目录
- `nexus_kb_backend/`：Django 后端（API、数据模型、检索、任务、Agent）。
- `frontend/`：Streamlit 多页面前端（登录、RAG、Agent、文档管理、数据看板）。
- `download_model.py`：下载本地 embedding/reranker 模型。
- `README.md`：总体架构、运行方式、技术说明。

## 3. 后端结构（nexus_kb_backend）

### 3.1 config（基础设施配置）
- `config/settings.py`：数据库、JWT、Celery、媒体目录等全局配置。
- `config/urls.py`：统一注册 API 路由（RAG、Agent、认证、反馈、管理看板）。
- `config/celery.py`：Celery 应用入口。

### 3.2 core（业务核心）
- `models.py`
  - 数据模型核心：
    - `KnowledgeBase`（知识库）
    - `Document`（原始文档 + 状态）
    - `DocumentChunk`（切片 + 向量）
    - `ChatSession` / `ChatMessage`（会话与消息）
    - `UserMemory`（用户长期记忆）
- `views.py`
  - `UploadDocumentView`：上传文档，触发异步处理。
  - `ChatView`：RAG 对话，流式返回内容 + 来源。
  - `AgentChatView`：智能体对话，流式返回状态 + 内容。
  - `KnowledgeBaseViewSet` / `DocumentViewSet`：知识库与文档管理。
  - `MessageFeedbackView` / `AdminDashboardView`：反馈与看板。
- `tasks.py`
  - `process_document_task`：文档解析、分块、embedding、摘要生成、入库。
  - `extract_user_memory_task`：从会话抽取用户长期偏好并写入向量记忆。
- `retrievers.py`
  - 检索路线：向量检索 -> 混合检索（向量+关键词）-> RRF 融合 -> rerank。
  - `MultiQueryRetriever` 会先改写查询，再汇总重排。
- `agent.py` + `tools.py`
  - 组装 Agent 与工具：联网搜索、知识库检索、数据库统计、Python REPL。

## 4. 前端结构（frontend）
- `app.py`：首页入口。
- `frontend_lib.py`：前端 API 封装、登录态/cookie、缓存与公共方法。
- `pages/0_用户中心.py`：注册/登录/注销。
- `pages/1_知识库对话.py`：RAG 对话页（可选知识库与文档范围）。
- `pages/2_全能智能体.py`：Agent 对话页（展示工具调用状态与反馈）。
- `pages/3_文档管理.py`：文档审核、删除。
- `pages/4_数据看板.py`：管理员指标面板。

## 5. 关键业务流程（必须理解）

### 5.1 文档入库流程
1. 前端上传文件到 `/api/upload/`。
2. 后端创建 `Document`，并触发 `process_document_task`。
3. Celery 任务解析文档、切分、向量化，写入 `DocumentChunk`。
4. 文档状态由 `pending` 走到 `active/reviewing/failed`。

### 5.2 RAG 问答流程
1. 前端调用 `/api/chat/`。
2. 后端通过 `MultiQueryRetriever` 多路召回与重排获取高相关 chunk。
3. 组装 Prompt（历史 + 检索上下文 + 文档摘要）调用 LLM。
4. 以 NDJSON 流式返回答案和来源。

### 5.3 Agent 流程
1. 前端调用 `/api/agent/chat/`。
2. 后端创建/加载会话，拼接历史消息与用户记忆。
3. Agent 按需调用工具（web/KB/db/python）。
4. 流式回传“状态 + 内容”，结束后保存消息并异步抽取记忆。

## 6. 新人建议学习路线
1. 先跑通系统（后端 + Celery + 前端），确认上传和聊天可用。
2. 先读 `models.py`，建立数据结构心智模型。
3. 再读 `views.py` 的两个主入口：`ChatView`、`AgentChatView`。
4. 然后读 `tasks.py`（离线处理）和 `retrievers.py`（在线检索）。
5. 最后读 `frontend/pages`，理解前端如何承接流式协议与会话管理。

## 7. 新人最容易踩坑
- 本地模型路径与 `download_model.py` 下载目录不匹配。
- `.env` 缺 key（DeepSeek/Tavily/数据库/Redis），导致接口超时或启动失败。
- 忘记启动 Celery，上传后文档状态一直不变。
- PostgreSQL 未启用 `pgvector/pg_trgm`，检索与索引功能异常。

## 8. 进入生产前建议
- 将硬编码配置（如 Agent 图表 URL）迁移到环境变量。
- 完善权限检查（当前部分接口对 session 归属校验仍可加强）。
- 为 retriever、任务、API 增加自动化测试。
- 统一日志与错误码，便于监控与排障。
